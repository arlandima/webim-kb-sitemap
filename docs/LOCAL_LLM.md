# Подключение локальной языковой модели

Приложение работает без LLM. Чтобы ответы формулировала модель (по-прежнему **только** по найденным фрагментам), достаточно указать OpenAI-совместимый сервер в файле `.env` (скопируйте `.env.example`) и перезапустить `python run.py`. Код поиска не меняется.

```ini
LLM_PROVIDER=openai
LLM_BASE_URL=http://localhost:8001/v1     # без /chat/completions
LLM_API_KEY=local                         # для локальных серверов — любая непустая строка
LLM_MODEL=<имя модели ровно как её видит сервер>
```

Проверка: `python scripts/check_llm.py` (реальный запрос по реальному вопросу, показывает время до первого токена) и страница `/admin` (строка «Языковая модель»).

> **Статус проверки.** Клиент протестирован автотестами на локальном имитационном OpenAI-совместимом сервере (стриминг SSE, `<think>`, ошибки, откат на извлекающий ответ). С реальными vLLM / SGLang / LM Studio / MLX в облачной среде сборки **не запускался** — ниже рекомендации, а не измерения. Названия моделей и флаги нужно сверить с актуальной документацией серверов.

## Windows-ПК, RTX 5090 32 ГБ

* **LM Studio** (самый простой путь под Windows): загрузите модель, включите Local Server (по умолчанию `http://localhost:1234/v1`), `LLM_MODEL` — идентификатор из LM Studio.
* **vLLM / SGLang**: обычно запускаются в WSL2 или Docker с GPU. Пример для vLLM:
  ```bash
  vllm serve <модель> --port 8001 --max-model-len 16384
  ```
  Порт 8001, чтобы не конфликтовать с приложением (8000). Из Windows в WSL2 сервер обычно доступен по `localhost`.
* Под 32 ГБ VRAM разумно брать квантованную модель класса 20–35 млрд параметров с хорошим русским (например, семейства Qwen3 или Gemma 3). Контекст запроса небольшой: ≈ 5 фрагментов × до 1 800 символов ≈ 3–4 тыс. токенов.

## Mac Studio M4 Max 128 ГБ

* **LM Studio** (MLX-модели): `http://localhost:1234/v1`.
* **MLX-сервер**: `mlx_lm.server --model <mlx-модель> --port 8001` → `LLM_BASE_URL=http://localhost:8001/v1`.
* 128 ГБ позволяют держать и более крупную модель (70B-класс в 4-bit); скорость генерации — вопрос отдельного замера.

## Приложение на одной машине, модель на другой

Запустите сервер модели с привязкой к сети (`--host 0.0.0.0`), откройте порт в брандмауэре локальной сети и укажите `LLM_BASE_URL=http://<IP машины с моделью>:8001/v1`. Не выставляйте такой сервер в интернет без аутентификации.

## Claude / Anthropic (опционально)

```ini
LLM_PROVIDER=anthropic
ANTHROPIC_API_KEY=...        # только в .env, не в Git
LLM_MODEL=<идентификатор модели>
```

Вопрос и найденные фрагменты документации уходят в облако Anthropic — учитывайте это политикой данных.

## Что происходит с рассуждающими моделями

Если модель выводит рассуждения в `<think>…</think>`, клиент скрывает их и не показывает пользователю. Для скорости лучше отключить режим рассуждений на стороне сервера/модели.

## GPU для эмбеддингов и реранкера (необязательно)

Эмбеддинги и реранкер считаются через ONNX Runtime; на CPU реранкинг 20 кандидатов занимает ≈ 2,5 с (4 vCPU, замер). Чтобы ускорить: на Windows `pip install onnxruntime-directml` (вместо `onnxruntime`), на машине с NVIDIA — сборка `onnxruntime-gpu`, подходящая к вашей версии CUDA/архитектуре (для RTX 50-й серии нужна свежая сборка; не проверялось). На Apple Silicon стандартный `onnxruntime` использует CoreML при `ORT_USE_GPU=1`. Приложение само выбирает доступный провайдер; при проблемах — `ORT_USE_GPU=0`. Альтернатива — `RERANK_CANDIDATES=12`.

## Смена моделей поиска

`EMBED_MODEL=multilingual-e5-small` — меньше и быстрее, но индекс нужно пересчитать (`python -m webim_ai.sync` посчитает эмбеддинги для новой модели; готовый индекс в репозитории — для `multilingual-e5-large`). `EMBED_MODEL=off` / `RERANK_MODEL=off` — режим только лексического поиска (качество заметно ниже, см. отчёт). Реранкер можно заменить на `jina-reranker-v2` без пересчёта индекса.
