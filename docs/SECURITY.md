# Безопасность и модель угроз

Прототип работает с публичными данными и локально; продуктовая эксплуатация потребует дополнительных мер (см. ниже).

| Угроза | Мера в прототипе | Проверка |
|---|---|---|
| Краулер уходит за пределы KB / SSRF через редиректы | Строгая канонизация, только `https://webim.ru/kb/…`; редиректы вручную с проверкой каждого шага; сторонние хосты и `?query` отбрасываются | `tests/test_crawler.py` |
| Нагрузка на сайт Webim | Пауза 0,3 с, кэш, условные запросы, пропуск неизменённых по `lastmod`, негативный кэш 404; ночной прогон без изменений = 1 запрос | тест инкрементальности |
| Вредоносный код в контенте (XSS) | HTML только разбирается; `script/style/iframe/form` отбрасываются; UI выводит текст через `esc()`/`textContent` — HTML документации не рендерится; блоки кода отображаются как текст и не исполняются | `test_parser_drops_scripts…` |
| Prompt injection из документации | Документация помечена как данные в системном промпте; из фрагментов удаляются теги `<source>` и строки-инъекции; ответ проверяется (несуществующие цитаты удаляются); при низкой уверенности LLM не вызывается | `test_prompt_injection_sanitized` |
| Галлюцинации | Ответ только по фрагментам, цитаты `[n]`, отказ при недостатке доказательств, отказ на неизвестные названия | `eval/run_eval.py` |
| Утечка секретов | Только переменные окружения / `.env` (в `.gitignore`); `.env.example` без значений; ключи не логируются и не попадают в UI | ручная проверка репозитория |
| Инъекции в поиск | Токены запроса экранируются в кавычки FTS5; SQL — параметризованный | `test_retrieval` |
| Небезопасные URL | `/api/article` принимает только URL внутри `/kb/`; внешние ссылки открываются с `rel="noopener"` | `test_article_and_tree` |
| Отказ в обслуживании | Ограничение длины вопроса (600), истории и размера контекста | `test_ask_validation` |

## Что НЕ сделано (нужно для продакшена)

* Аутентификация/авторизация, ограничение частоты запросов (rate limit), CORS/CSP-заголовки, HTTPS-терминация — по умолчанию сервер слушает только `127.0.0.1`.
* Журналирование запросов пользователей и политика хранения (сейчас в памяти хранятся последние 50 запросов для `/admin`).
* Если LLM облачный — вопросы и найденные фрагменты уходят провайдеру; для внутренних данных использовать локальную модель (`docs/LOCAL_LLM.md`).
* Для не публичных источников — разграничение доступа на уровне документов.
